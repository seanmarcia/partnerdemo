GitHub for Nonprofits

Partner API integration guide

For our partners

Check nonprofit validation

Use these read-only endpoints to check whether a GitHub user or organization is associated with a validated nonprofit. Test from your terminal, then make the same HTTPS request from your application's backend.

Keep your partner API key on the server. Use the key supplied by the GitHub for Nonprofits team, not a GitHub personal access token. Store it in an environment variable or secret manager. Never put it in frontend JavaScript, mobile app bundles, URLs, source control, or logs. This guide does not collect a key or make API requests.

Choose an endpoint

GitHub username

GET /api/users?username=octocat

Returns true if the user is linked in GitHub for Nonprofits to at least one validated GitHub organization.

GitHub organization

GET /api/organizations?name=your-org

Returns true if that GitHub organization is recorded as validated in GitHub for Nonprofits.

Use the GitHub login, not a display name, email, numeric ID, or profile URL. The user endpoint takes username; the organization endpoint takes name. A missing parameter returns false, not an input error.

Base URL: https://nonprofits.github.com

1. Test from your terminal

Copy either command below, replace PASTE_YOUR_PARTNER_API_KEY_HERE with your partner API key, replace the example login, and paste the command into your terminal. No variable setup is needed. These commands use Bash or Zsh and a modern curl with --fail-with-body support (7.76 or later).

Key privacy: a key pasted directly into a command may be saved in shell history and visible in process arguments. Use a trusted terminal, follow your organization's shell-history policy, and do not share commands or screenshots containing the real key. For application code, keep using a server-side environment variable or secret manager.

Check a user

Replace octocat with the GitHub username you want to test.

curl --include --fail-with-body --get \
  --connect-timeout 5 --max-time 15 \
  'https://nonprofits.github.com/api/users' \
  --header 'Authorization: Token token="PASTE_YOUR_PARTNER_API_KEY_HERE"' \
  --header 'Accept: application/json' \
  --data-urlencode 'username=octocat'

Check an organization

Replace your-org with the GitHub organization login you want to test.

curl --include --fail-with-body --get \
  --connect-timeout 5 --max-time 15 \
  'https://nonprofits.github.com/api/organizations' \
  --header 'Authorization: Token token="PASTE_YOUR_PARTNER_API_KEY_HERE"' \
  --header 'Accept: application/json' \
  --data-urlencode 'name=your-org'

--include shows the HTTP status and response headers. --get puts the encoded identifier in the query string; no request body is needed. Example names are illustrative and are not guaranteed to be validated.

2. Read the response

Successful requests return HTTP 200 with a JSON boolean as the entire body: true or false. It is not a string or an object such as {"validated": true}.

200 + true
A matching validated organization was found, directly or through the user's recorded organization links.
200 + false
No matching validated record was found. This also covers unknown names, missing query parameters, and users without a linked validated organization. It does not distinguish between those cases.
401 Unauthorized
Check that you supplied the correct partner API key and the Authorization header shown above. An authentication failure is not a validation result.
406 / 415
Request a JSON response with Accept: application/json. Do not request an HTML format. For these GET requests, omit the body and Content-Type header.
Other HTTP errors, timeouts, or unexpected responses
Report an integration error or temporarily unavailable state. Never turn a failed request into false. Curl exits nonzero for HTTP failures with the supplied flag, and also for connection failures or timeouts.

3. Add it to your application

  1. Store your partner key in your backend's secret manager or NONPROFITS_API_KEY environment variable.
  2. From your backend, send an HTTPS GET to the appropriate endpoint. URL-encode the identifier and include the Authorization and Accept headers above.
  3. Set a request timeout, check the HTTP status, parse the JSON, and require a boolean result. Only a successful boolean response should drive your validation decision.
  4. Return the decision to your frontend without exposing the partner key. Protect your own backend endpoint with your application's authentication and authorization.

Why server-side? Browser-to-API calls from another origin require CORS permission and expose the key to client-side code. Backend HTTP clients and curl are not subject to browser CORS restrictions. No CORS change is needed for this integration approach.

Example: server-side JavaScript (Node.js 20+)

The same HTTP request works from Ruby, Python, PHP, Java, or any backend with an HTTPS client. This function returns a boolean on success and throws on failure; handle errors using your application's normal error handling.

async function checkNonprofit(kind, login) {
  const key = process.env.NONPROFITS_API_KEY;
  if (!key?.trim()) throw new Error("Missing partner API key");
  if (typeof login !== "string" || !login.trim()) {
    throw new Error("A GitHub login is required");
  }
  if (kind !== "user" && kind !== "organization") {
    throw new Error("Use user or organization");
  }

  const url = new URL(
    kind === "user" ? "/api/users" : "/api/organizations",
    "https://nonprofits.github.com"
  );
  url.searchParams.set(
    kind === "user" ? "username" : "name",
    login.trim()
  );

  const response = await fetch(url, {
    headers: {
      Authorization: `Token token=${JSON.stringify(key.trim())}`,
      Accept: "application/json"
    },
    signal: AbortSignal.timeout(15000),
    redirect: "error"
  });
  if (!response.ok) {
    throw new Error(`Nonprofits API returned HTTP ${response.status}`);
  }

  const validated = await response.json();
  if (typeof validated !== "boolean") {
    throw new Error("Expected a JSON boolean from Nonprofits API");
  }
  return validated;
}
